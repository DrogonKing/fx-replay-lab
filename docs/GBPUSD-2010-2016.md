# "Download GBPUSD 2010–2016 at 1 minute" — what actually answers

Measured 2026-10-21 from this host. Scripts: `scripts/probe-gbpusd*.py`, `probe-bulk.py`.

## Answer: Dukascopy, and only Dukascopy

Every other free source fails this specific request, for a different reason each.

### The URL month is ZERO-indexed

```
GBPUSD/2010/00/04/...  = 2010-01-04
GBPUSD/2016/08/02/...  = 2016-09-02
```

Getting this wrong shifts every request by one month and produces a silent 404 or wrong data.
This is the single easiest way to break a bulk downloader.

### Throughput: slow, and it 503s

Ten consecutive days of GBPUSD 2014-06:

```
2014-06-02: OK    23876ms
2014-06-03: OK    78612ms
2014-06-04: OK    42548ms
2014-06-05: FAILED (503) 68249ms
2014-06-06: OK    55296ms
```

Latency is **wild and not a rate limit** — a 2010 day re-fetched later took 13.8s after the
same day took 0.5s earlier. The server is simply under variable load.

**Cost estimate for the full 2010–2016 GBPUSD pull:**

| | |
|---|---|
| day-files | **2557** (7 years) |
| median latency | ~25–55s |
| single-threaded | **~2–3 hours** |
| with 4 parallel workers | **~35–50 minutes** |
| compressed size | **~27 MB** total |

So it is a one-time download measured in hours, not minutes. That is acceptable for history —
but the downloader **must be resumable** and **must retry**, because 1 in 10 files fails.

### Why nothing else works for this request

| Source | Why it fails 2010–2016 at 1m |
|---|---|
| **TwelveData** | demo key returns **401** for `GBP/USD` at all (only `EUR/USD` and `USD/JPY` are covered). Even with a real key, 5000 bars of 1min is **~3.5 days** — the API has no deep intraday history |
| **AlphaVantage** | 25 requests/day, and `outputsize=full` returns ~4 days of 5min |
| **Yahoo** | 429 all session, and 1m history is ~7 days |
| **HistData** | `get.php` returns **0 bytes** — the form's `tk` token is empty in the HTML and filled by JavaScript, and the POST is rejected without it. The page loads and the form exists, but the download needs a real browser session or a manual click |
| **FXCM candledata** | 404 on every path |
| **Stooq** | daily only |

**Conclusion:** Dukascopy is the only free source that can serve this request at all. That is
not a preference, it is the only option that answered.

## What the downloader must get right

1. **Zero-indexed months** in the URL.
2. **Retry with backoff** — 503s are routine, ten attempts with a 4s pause was needed.
3. **Resumable** — track completed days, because 2557 files take hours and will be interrupted.
4. **Parallel, but gently** — 4 workers is a sensible ceiling; the server already struggles.
5. **Decode**: LZMA, then 24-byte records of `uint32 seconds` + `uint32 open, close, low, high`
   in 1e-5 points + `float32 volume`. Reading the prices as float32 gives zeros.
6. **Skip empty records** — a record with open = 0 is a minute with no ticks (weekend/holiday);
   counting it as a bar would put a fake zero price in the chart.
7. **Cache to disk as CSV or binary**, never re-download. The app's replay should read local
   files, not hit the network at runtime.

## Note on data quality

This is Dukascopy's own book, so its prices differ from any other broker's by a few pips — the
measured median against TwelveData was **6 pips**. For a backtest that is fine as long as the
whole test uses one source; it is not fine to mix sources within a test.
