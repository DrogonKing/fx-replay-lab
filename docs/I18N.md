# Persian and RTL

Switch language in the toolbar (**Language / زبان**). English is the default; Persian is
chosen automatically if the browser prefers it and nothing is stored.

The choice is saved to `localStorage` and survives a restart.

## How the direction works

`<html dir>` is set to `rtl` for Persian. That is the **only** direction switch: no
per-component RTL props, no mirrored stylesheet copy.

CSS Grid and Flexbox already mirror themselves under `dir="rtl"` — the first grid column
is placed at the physical right, and a row flex container starts from the right. So the
panel moves to the left, the drawing rail to the right, and the toolbar reverses, for free.

### The bug this cost

The first version added explicit overrides:

```css
[dir="rtl"] .app {
  grid-template-columns: 280px 1fr 44px;
  grid-template-areas: "toolbar toolbar toolbar" "panel chart rail";
}
```

That **cancelled** the mirror instead of applying it. Measured in the running app:

```
panel offsetLeft 1160 · chart 44 · rail 0     <- identical to LTR, nothing had mirrored
```

Direction-aware overrides on a layout engine that already handles direction are not
neutral; they re-break it. After deleting them:

```
panel 0 · chart 280 · rail 1396               <- correctly mirrored
```

**Charts are never mirrored.** The time axis still runs oldest→newest left-to-right and
the price scale stays on the right. A reversed time axis would be a bug, not a
translation.

## Numbers stay Latin

Every numeric value keeps ASCII digits and LTR order in both languages:

```
قیمت 1991.71        مارجین 0 / 10000        ریسک / ریوارد 100 / 200 (1:2.00)
```

Persian-Indic digits (۰۱۲۳) were rejected deliberately. Prices, lot sizes and P/L are
copied into broker statements, spreadsheets and other tools; `۱۹۹۱.۷۱` cannot be searched,
matched or pasted. The locale changes the *direction of the words*, not the numbers.

Digits are pinned with `direction: ltr; unicode-bidi: isolate` so a number inside an RTL
sentence cannot be reordered by the bidi algorithm.

## The catalogue

`src/core/i18n.ts` holds both languages as a flat key namespace (`trade.buy`,
`news.paused`, ...). `t(lang, key, vars)` interpolates `{placeholders}`.

Three properties are enforced by tests, because a half-translated UI is worse than an
untranslated one:

1. **no missing keys** — `missingKeys(lang)` must be empty for every locale
2. **no stale keys** — a translation whose key no longer exists in English fails
3. **no dropped placeholders** — `news.paused` must keep `{reason}` in every language, or
   the pause message renders with no explanation

A missing key returns **the key itself**, not an empty string. An empty button is
invisible and unreportable; `trade.buy` on screen is an obvious bug report.

## Typography

Persian needs a taller line box than the 11px English UI: `line-height: 1.7` and a wider
font stack (`Vazirmatn`, `Noto Naskh Arabic`, `Segoe UI`, `Tahoma`). Vazirmatn is not
bundled — if it is not installed the system Naskh face is used, which the app has been
verified against.

Labels are also allowed to wrap in the order form (`flex-wrap` on the break-even row),
because Persian labels are longer: *حد ضرر (پوینت)* against *SL (pts)*.

## What is not translated

- **Chart internals** — the OHLC legend, `Lightweight Charts` attribution and the price
  axis keep English/Latin, consistent with not putting a vendor name or logo in the UI.
- **Strategy and indicator names** — `EMA`, `RSI`, `Bollinger` are identifiers.
- **Journal CSV export headers** — deliberately stable English so a spreadsheet from a
  Persian session matches one from an English session.
- **Console/debug messages** — developer-facing.
- **Error strings from the core** (`"buy limit 2050 is above the market"`) are still
  English. They are surfaced verbatim in the trade panel, so a Persian user sees English
  validation text. That is the main remaining gap.

## Where it lives

- `src/core/i18n.ts` — catalogue, `t()`, `pickLang`, number/date formatting
- `src/renderer/i18n-context.tsx` — provider, `<html dir>` switching, persistence
- `src/renderer/styles-rtl.css` — the small amount that genuinely needs direction rules
- `tests/i18n.test.ts` — 28 tests including catalogue completeness
- `scripts/i18n-smoke.sh` — switch, mirror, Latin digits, reload persistence in the app
